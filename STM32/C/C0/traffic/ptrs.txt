type Volatile_UInt32_Ptr is access all UInt32
  with Real_Address; -- Ensures full pointer operations
pragma Volatile (Volatile_UInt32_Ptr);

-- Usage:
CCR_Reg : Volatile_UInt32_Ptr;
Or using GNAT's built-in address conversions:

Ada
use System.Address_To_Access_Conversions;

package UInt32_Ptrs is new System.Address_To_Access_Conversions (UInt32);

-- Usage:
CCR_Reg : UInt32_Ptrs.Object_Pointer;
To assign and write to it:

Ada
-- Point to TIM1 CCR1
CCR_Reg := UInt32_Ptrs.To_Pointer (TIM1_Periph.CCR1'Address);

-- Dereference and write (equivalent to *ccr_reg = val;)
CCR_Reg.all := 128;
Option 2: Address Overlay (Zero-Overhead Ada Style)
If the register address is known or passed in by address, the most common Ada pattern avoids access types ("pointers") entirely. Instead, you declare a Volatile variable and overlay it directly onto the hardware address:

Ada
CCR_Reg : UInt32 with
  Volatile,
  Address => TIM1_Periph.CCR1'Address;

-- Writing to it is just a normal variable assignment:
CCR_Reg := 128;
Option 3: Array Indexing (Best for TIM1 Channels 1..4)
If ccr_reg was originally C code indexing into TIM1's capture/compare registers (CCR1 through CCR4), you can map the 4 registers as an array without using pointers at all:

Ada
type CCR_Array is array (1 .. 4) of UInt32
  with Component_Size => 32;

TIM1_CCR : CCR_Array with
  Volatile,
  Address => TIM1_Periph.CCR1'Address;

-- Usage:
TIM1_CCR (Channel) := Duty_Cycle;
Option 1 gives you exact C pointer semantics, but Option 3 is usually the cleanest for TIM1 PWM channel management!
